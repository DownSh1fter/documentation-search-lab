# Documentation Search Lab

[English version](README.md).

Учебный проект по поиску информации в технической документации. Цель — сравнить поиск по словам и семантический поиск, измерить качество выдачи, разобрать ошибки и научиться возвращать ответы с подтверждающими ссылками на источники.

## Зачем этот проект

Это личный учебный проект для практики ML-инженерии: подготовки корпуса, создания воспроизводимой выборки для оценки, расчёта метрик поиска, анализа ошибок и разработки API. Результаты будем записывать вместе с версией данных и ограничениями оценки.

## Что делает проект

Documentation Search Lab помогает находить информацию в заданном наборе технических документов. Например, по вопросу «Как открыть текстовый файл с нужной кодировкой?» система ищет подходящие фрагменты документации Python. В режиме RAG локальная языковая модель затем пытается составить ответ по найденным фрагментам и указать источники. Текущие примеры и оценка поиска ориентированы на вопросы на английском.

| Режим | Назначение | Где доступен сейчас |
| --- | --- | --- |
| TF-IDF | Поиск по совпадению слов в вопросе и документах | CLI, веб-интерфейс и поисковый API |
| Семантический поиск | Поиск с помощью эмбеддингов предложений и косинусного сходства | CLI |
| RAG | Поиск подтверждений и генерация ответа локальной Qwen со ссылками на источники | CLI |

Fine-tuning адаптирует поисковую эмбеддинг-модель на размеченных парах «вопрос — фрагмент». Генератор Qwen при этом не дообучается. Проверка ID цитат подтверждает, что указанный источник был передан модели, но не доказывает, что он подтверждает каждое утверждение ответа.

## Где можно применять

Сейчас проект можно использовать локально для поиска по включённой документации Python, сравнения методов поиска и практики подготовки данных, адаптации моделей, оценки качества и анализа ошибок. Он также подходит для демонстрации NLP-поиска и RAG в портфолио.

Ниже — возможные направления адаптации, для которых нужны доработки:

| Сценарий | Пример | Что потребуется |
| --- | --- | --- |
| Документация команды | Поиск описаний сервисов и инструкций для новых сотрудников | Подготовка и обновление корпуса, разграничение доступа при необходимости |
| Поддержка продукта | Поиск ответов в руководствах и FAQ | Загрузка документов продукта и оценка на типичных вопросах пользователей |
| База знаний QA | Поиск требований к API и ожидаемого поведения продукта | Загрузка спецификаций и проверка ответов по версионируемым источникам |
| Личная техническая база знаний | Поиск по заметкам и инструкциям | Загрузчики документов и процесс обновления индекса |

Текущий корпус содержит выбранные разделы документации Python. Автоматическое подключение произвольных PDF, сайтов и корпоративных баз знаний пока не реализовано. Веб-интерфейс и поисковый API используют только TF-IDF; семантический поиск и RAG доступны через CLI.

RAG остаётся экспериментальным: опубликованный smoke-тест не проходит критерии качества ответов и подтверждения цитатами. Перед использованием ответов изучите [результаты оценки](reports/EVALUATION_RESULTS.md). Для промышленного применения потребуются более широкая оценка, улучшение подтверждения ответов источниками и работа над развёртыванием, мониторингом и управлением доступом.

## Текущий статус

Система индексирует 206 фрагментов с семи страниц Python Tutorial версии 3.15.0 и справки по встроенной функции `open()`. В наборе 32 англоязычных вопроса с ручной разметкой релевантных фрагментов и переводами на русский. Реализованы TF-IDF и плотный семантический поиск, контрастивное дообучение эмбеддингов, а также локальный RAG с поиском подтверждений, генерацией с цитатами и отказом при нехватке данных. На текущем holdout из восьми вопросов fine-tuning улучшил плотный поиск, но TF-IDF пока лучше по Recall@1 и MRR@5. Smoke-тест RAG на шести случаях не проходит критерии качества ответов и цитирования: RAG реализован, но надёжность ответов пока не подтверждена. Результаты приведены в `reports/EVALUATION_RESULTS.md`.

## Быстрый запуск

```bash
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell
.venv\\Scripts\\Activate.ps1
python -m pip install -e .
python scripts/build_corpus.py
python -m doc_search.evaluate
python -m doc_search.cli "How do I read a text file?"
```

### Семантический поиск, fine-tuning и RAG

```bash
python -m pip install -e '.[semantic,rag,train]'
python -m doc_search.evaluate --mode semantic --model sentence-transformers/all-MiniLM-L6-v2 --questions data/questions-holdout.jsonl --split-name holdout-v1 --output reports/semantic-holdout.json
python -m doc_search.finetune --questions data/questions-train.jsonl --output models/retriever --epochs 2
python -m doc_search.evaluate --mode tfidf --questions data/questions-holdout.jsonl --split-name holdout-v1 --output reports/tfidf-holdout.json
python -m doc_search.evaluate --mode semantic --model models/retriever --questions data/questions-holdout.jsonl --split-name holdout-v1 --output reports/fine-tuned-holdout.json
python -m doc_search.cli "How do I read a text file?" --mode semantic --model models/retriever
python -m doc_search.cli "How do I read a text file?" --mode rag --model models/retriever
python -m doc_search.evaluate_rag --model models/retriever --answer-model Qwen/Qwen2.5-1.5B-Instruct
```

Семантический поиск и fine-tuning работают локально через Sentence Transformers; при первом запуске загружаются веса модели. Fine-tuning использует размеченные пары из train-части и loss для ранжирования с множеством негативных примеров. RAG находит фрагменты и передаёт подтверждения локальной instruction-tuned модели Qwen для генерации краткого ответа. Проверяются ID цитируемых источников; при слабом поиске или отказе модели система воздерживается от ответа. Зависимости и веса моделей скачиваются при первом запуске. Качество ответов проверяйте на отложенном наборе.

Набор для оценки RAG пока содержит шесть вручную подготовленных случаев: четыре вопроса с ответом в корпусе и два без ответа. В `reports/RAG_REVIEW.md` описаны ручная разметка правильности, поддержки источниками и цитат, а также предварительные критерии smoke-теста. Для общих выводов набор нужно расширить и отделить финальную выборку.

### Веб-интерфейс

После установки проекта запустите `start-search.bat` двойным щелчком. Откроется страница поиска в браузере. Введите вопрос на английском, выберите число результатов и нажмите «Найти». В карточках показаны фрагмент документации, оценка TF-IDF и ссылка на исходную страницу. Пока сервер работает, окно консоли нужно оставить открытым; чтобы остановить его, нажмите `Ctrl+C`.

Также интерфейс можно запустить из активированного окружения командой `python -m doc_search.web`, затем открыть `http://127.0.0.1:8000`.

## Этапы проекта

1. Определить задачу, источники корпуса и формат оценки.
2. Измерить лексический бейзлайн с помощью Recall@k и MRR.
3. Сравнить реализованный семантический поиск с лексическим бейзлайном.
4. Дообучить модель на train-части; сравнить с TF-IDF и базовыми эмбеддингами на отложенных вопросах.
5. Генерировать локальные ответы RAG с источниками и отказом при нехватке подтверждений.
6. Упаковать API и веб-интерфейс для воспроизводимого запуска через Docker.

## Принципы оценки

- Разделять вопросы для разработки и итоговую отложенную выборку.
- Сравнивать изменения поиска на одном и том же зафиксированном наборе вопросов.
- Публиковать метрики поиска и примеры ошибок; не приводить единственную цифру accuracy без контекста.
- Записывать версию корпуса, название модели, настройки и случайное зерно вместе с результатами.

## Бейзлайн TF-IDF

Бейзлайн использует англоязычный TF-IDF с униграммами и биграммами; результаты ранжируются по косинусному сходству. Результат на текущем наборе для разработки:

| Метрика | Результат |
| --- | ---: |
| Recall@1 | 0.594 |
| Recall@3 | 0.719 |
| Recall@5 | 0.875 |
| MRR@5 | 0.680 |

У четырёх из 32 вопросов нужный фрагмент не попал в первую пятёрку. Это результаты на небольшом вручную размеченном наборе для разработки, а не финальная оценка на отложенной выборке. Метрики и разбор ошибок находятся в `reports/`.

## Формулировки для резюме

- Разработал поиск по технической документации: TF-IDF и семантический поиск на Sentence Transformers; оценивал ранжирование метриками Recall@k и MRR.
- Реализовал контрастивное дообучение эмбеддинг-модели на размеченных парах «вопрос–фрагмент» с сохранением модели и оценкой на holdout; на текущих восьми вопросах оно улучшило базовый плотный поиск, но не превзошло TF-IDF.
- Реализовал локальный generative RAG: поиск подтверждений, генерация Qwen по контексту, проверка ID цитат и отказ при нехватке данных. Smoke-тест из шести случаев не проходит критерии качества ответов и цитирования; надёжность пока не подтверждена.
